# NetworkExpression · 计算机网络可视化实验室

中文、离线运行的计算机网络学习网站。以五层体系结构组织内容，通过设备拓扑、协议专属观察视图和逐步解释，回答“谁向谁发了什么、哪些状态改变、为什么”。

## 本地启动

Node.js 18+，网站运行和单元测试没有第三方依赖：

```bash
npm run dev
# 打开 http://localhost:4173
npm test
```

## 课程覆盖

29 个实验、143 个基础步骤、66 条概念索引，每个实验有一道概念自测。

| 学习位置 | 可逐步演示的主题 | 主要观察方式 |
| --- | --- | --- |
| 贯通基础 | 分层封装、一次网页访问全程 | 端系统协议栈、逐跳重新封帧、跨层协作 |
| 物理层 | 比特、带宽与时延 | 信号波形、L/R 与 d/v 的计算对照 |
| 链路层 | 交换机 MAC 学习、ARP、VLAN、Wi-Fi | 星形拓扑、泛洪分支、MAC 表、广播边界、退避与链路 ACK |
| 网络层 | 子网与最长前缀、IPv4 转发、ICMP、traceroute、MTU、NAT、IPv6、OSPF、BGP | 路由表、TTL、地址转换、邻居缓存、冗余路径与故障收敛 |
| 传输层 | UDP、TCP 握手、超时重传、流量控制、拥塞控制、关闭连接 | 时序图、双方状态、字节缺口、缓冲窗口、cwnd 曲线 |
| 应用层 | DNS、DHCP、HTTP、缓存、TLS、邮件、HTTP/2 与 HTTP/3 | DNS 分支服务、租约、条件请求、认证过程、邮件投递与独立流 |

三个实验可切换条件并从起点重放：

- IPv4 转发：初始 TTL=3 成功到达，对照 TTL=1 在网关丢弃并返回 ICMP。
- TCP 可靠传输：第一段丢失后的超时恢复，对照没有丢失的累计确认。
- HTTP 缓存：内容不变返回 304，对照内容改变返回 200 与新消息体。

概念索引补充 OSI、协议与服务、分组/电路交换、CRC、STP、RIP、SLAAC、SACK、CDN 等相邻主题，并明确哪些仅为概念说明，哪些已经有展开的演示。当前是本科网络课程的入门主线，不宣称穷尽无线标准、密码学、路由策略和所有协议实现细节。

## 怎样观察

1. 在五层地图中选择协议，或用目录搜索和层级筛选。
2. 阅读“实验起点与边界”，区分教学条件和真实部署。
3. 用上一步、下一步、步骤跳转或自动播放控制节奏。自动播放可选 4/6/10 秒；默认 6 秒。
4. 在拓扑中看设备、实际连接与箭头方向；点击设备可查看职责。本地处理不绘制传输箭头，广播显示分支，故障链路不会继续承载后续包。
5. 在下方的协议栈、时序图、状态表、窗口或曲线中检查状态；文字解释说明因果和容易混淆的边界。
6. 浏览当前实验分支的全部步骤后完成自测；完成和答题记录保存在浏览器 localStorage。清理站点数据会清除进度，存储不可用时演示仍可运行。

手机使用纵向拓扑布局，可切换横向全图；控件支持键盘，SVG 设备和时序事件可用 Enter / 空格激活，当前步骤通过独立 live region 通知辅助技术。减少动态效果偏好会关闭脉冲动画。

## 内容边界与来源

拓扑使用主机、交换机、路由器、AP、服务器等设备，不把协议层画成路径上的设备。DNS 云节点及邮件服务连线合并了底层网络，页面明确标注。帧与报文、序号、时延和地址均为教学示意，不是真实抓包、流量模拟或性能预测。

各实验提供原始标准链接，包括 IETF RFC 826、1034/1035、2131、1812、9293、5681、8200、4861、2328、4271、9110/9111、8446、9000 等，以及 IEEE 802 标准家族。标准链接需要联网，但加载网站与所有教学功能不请求外部资源。

## 结构与扩展方式

| 文件 | 职责 |
| --- | --- |
| `src/lessons.js` / `src/lessons-extended.js` | 原有八个实验的数据与完整课程入口 |
| `src/curriculum.js` | 五层地图、21 个新增实验、题目与关键词 |
| `src/topology.js` | 设备与链路模板、显式路径、原有课程的拓扑接入 |
| `src/experiments.js` | 三组条件对照的独立故事板，不修改原始课程 |
| `src/visuals.js` | 拓扑、手机布局、设备观察和六类协议视图 |
| `src/main.js` | 导航、统一播放器、焦点与可访问性、目录和自测 |
| `src/learning.js` / `src/glossary.js` | 本地进度、筛选、题目和概念索引 |
| `src/styles.css` | 页面布局、设备图与响应式样式 |
| `tests/` | 课程、进度、拓扑、条件分支、渲染和交互状态检查 |
| `scripts/browser-check.mjs` | 可选真实浏览器回归与截图，不是网站依赖 |

新增实验时复用课程数据格式：每步提供发送者、接收者（本地处理时为 null）、消息、解释和观察状态；多播/泛洪或特定路由使用显式 `routes`。选择拓扑 `kind` 和观察 `view`，同步补充假设、标准、自测、层级地图与概念入口。不要复制整套页面逻辑。

## 验证

`npm test` 检查每条路径是否经过有效链路、故障边是否被绕开、VLAN 广播边界、本地操作没有虚构箭头，以及课程、自测、进度与播放器状态。

可选的浏览器检查需要另行安装 Playwright 与 Chromium（无需加入本项目依赖）：

```bash
# 先启动 npm run dev，然后使用已有的 Playwright 安装
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node scripts/browser-check.mjs
```

可设置 `PLAYWRIGHT_BROWSERS_PATH` 指向浏览器安装目录、`TEST_URL` 指向本地服务、`BROWSER_ARTIFACTS` 指定截图目录（默认 `/tmp/network-expression-check`）。检查会实际遍历所有步骤与自测、条件分支、键盘与焦点、自动播放、搜索、进度恢复、存储禁用，以及 320/390/768/1920 像素布局；同时检测运行错误和意外外部请求。教学复核记录见 [docs/validation.md](docs/validation.md)。
